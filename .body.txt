Per-namespace evidence bundles (`record.json`, `findings.json`, `audit.log`, `report.md`, `receipt.json`) sit under `i18n/audits/evidence/vi/<namespace>/cg1/`; each ledger row's `note` cites its `record.json`. The audit sessions were read-only and wrote `findings.jsonl`/`progress.log`/`summary.md`, not a shell log, so each `audit.log` carries those records verbatim plus the applier's computed hashes; no command output is invented.

**Audited input is committed, not scratchpad.** `input_hashes.audited_patch_file` used to hash an out-of-tree scratchpad file, which no reader could re-hash, so "patch values byte-equal to catalogue values" was self-attested. Every bundle now binds `i18n/audits/evidence/vi/_input/cg1.json` instead (`input_hashes.audited_input_manifest` = that file's sha256): SHA-256 of each of the 1311 shipped values as the auditors judged them, a `manifest_sha256` self-hash, and `remade_by_remediation` listing the 74 keys changed by remediation after the first audit round (core-fix and core-fix2 `changes.jsonl`, sessions in each `record.json`; 4 keys were remade twice). For every key the audited patch value equals the shipped value byte for byte (checked when the manifest was built; none needed reconciling), and `tests/unit/i18n/test_audit_input_manifests.py` recomputes every entry from the catalogue on each run. No value, verdict or severity was changed; receipts were re-hashed.

### Tests fixed (these failed on the first push of this PR)

Both asserted the committed corpus lacked a namespace that the locale PRs supply: `test_relay_login.py::test_actual_shipped_missing_namespace_uses_english_metadata[vi]` and `test_sdk.py::test_sdk4_explicit_locale_and_english_child_fallback` (`wire.errors.sdk_startup` cases). Mechanism chosen (shared commits `09ee36f66c0` + `9e853be12e6`, identical on all four locale PRs, first landed on #3229): **derive the expectation from the committed tree, and pin the absent path on a constructed tree.** Why: asserting "locale X lacks namespace Y" is a statement about the translation wave, not the fallback, so every wave reddened it; reading the tree keeps the test discriminating while it stops encoding which namespaces are translated today.

- For each case the test asks whether `local_operator/i18n/catalogues/<rendered>/<namespace>.json` exists and carries the key. Present: the page/refusal must be that locale's own copy, `lookups == [rendered]`. Absent: English whole, `lookups == [rendered, "en"]`.
- New `test_absent_namespace_falls_back_to_english_page` and `test_sdk4_absent_child_namespace_falls_back_to_english` build a synthetic catalogue root where the namespace is genuinely missing, so the fallback is proven whatever the catalogues contain. Negative control (run on #3229): disabling the `en` fallback in `messages.render` turns them red (`4 failed, 7 passed`); reverted.
