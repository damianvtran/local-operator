# Corrections and derivations — EXPLORATORY v1

The original figures/report must not be republished as evidence of current
performance. The independent review identifies methodological defects more
important than the reproducible arithmetic. This kit is a historical audit,
not a repaired experiment. Read `reviews/REVIEW-RIGOR-R1.md` (R1–R10).

Prompt for tier selection = uncached + cache read + cache creation tokens.
`cache_creation` provides 5m/1h subtotals; they must sum to aggregate creation.
Output already includes thinking. Per-call observed cost is the sum of all five
token × rate products / 1e6. Per-run observed cost sums **every** priced
`v1/messages` call, including title, selection and compaction calls. Each call
and each run reconciles against OpenRouter `usage.cost`; the figure is not an
independent invoice. No rate is applied to discovery or missing-usage rows.
The single missing-usage message belongs to the known Claude Code model-error
run and surprisingly has HTTP **200**; HTTP status alone does not establish
successful inference. That run is retained and flagged as infrastructure failure.

All 1,533 priced requests sum to $36.909711435. Rep 0 sums to $32.766771485;
6 smoke runs sum to $4.142939950. Earlier aborted/smoke logs mentioned in the
review are outside the frozen input and cannot be independently regenerated by
this kit. The broader spend counter is not substituted for the snapshot sum.
One-hour writes and Haiku >100k have no observations in this snapshot.

## Exact legacy cold algorithm (R2)

For each run, in **metering-file order**, choose its first priced call with
`n_tools > 0` (the original report's definition of main). Then:

```
cold_cost = observed_cost + first_main.cache_read_input_tokens * (2.50 - 0.10) / 1e6
```

This reproduces all 180 historical rows. It is **not** first HTTP call, first
side call, a cold execution, or an estimate of all possible cross-run reads.
Codex's one-tool compaction calls count in the old main-call fields/growth;
the historical `call_sequences.ctx` instead uses **n_tools > 1**. The two
notions are preserved and named, rather than silently made equivalent.
All-call cost sequences contain side calls too. Growth is a median over only
runs that reached call k, capped at 20, and must not be interpreted as a
fixed-population curve. Concurrent side calls cause start timestamps to be
out of file order; historical log order is intentionally preserved.

The additionally reported `cold_cross_run_estimate_usd` implements the review's
stricter heuristic: sort requests within run by start timestamp; keep a maximum
established prefix per served model. On each call, excess read is
`max(0, read - established)`; add excess × (5m-write rate − hit rate) / 1e6,
then set established to `max(established, read + creation)`. It includes side
calls and is still a counterfactual, not a measured cold result or proven cache
ownership. Timestamp order matches `reviews/cold.py`. Historical cold and this
alternative are shown with observed values, with equal visual prominence.

## Exact Codex historical sensitivity (R1/R5)

For each of the **four full-arm Codex runs separately**:

1. Keep priced calls with `n_tools > 1` (exclude one-tool compaction calls).
2. `prefix = min(cache_read + cache_creation)` over those calls.
3. Keep the first such call's observed cost unchanged.
4. For all later such calls, sum the **signed** adjustment
   `(prefix - cache_read) * (2.50 - 0.10) / 1e6`.
5. `codex_cache_corrected_cost = observed_cost - adjustment`.

Do not clamp the adjustment or select only the visibly expensive run. Exact
recovery from logs and parity with all four historical rows shows that review
R1's prose "applied to 1 of 4" is incomplete: the formula changes **three**
rows, including two slight **increases** where a read exceeds the minimum
prefix. Minimum prefixes: 374725, 376446, 376424, 376472 tokens, in original
task order eb303e01, aceb0368, 81c425f5, bc2b57f3. Per-run sensitivities:
$1.8708995, $2.9996456, $6.5050536, $3.5656837.

The $3.7353206 mean is a **historical post-hoc sensitivity estimate**, not a
measured result. The measured mean is **$5.7520388**. All raw costs remain
unchanged. Historical compatibility keys retain old values to make the audit
complete, but neither adjusted dollars nor the old ratio is headlined or
plotted. Root cause, causal effect and quality consequences were not established
by this repricing. Corrected model-metadata runs are different observations and
must not be conflated with this frozen v1 artifact.

## Cost components, classifier, and statistical limits

Unlike the old stacked figure, the replacement includes **all uncached input**.
It prices components per served model, not one rate applied to aggregate
mixed-model counts. Side-call cost is a subset annotation, never an extra stack.
Totals reconcile per run and at the long-task mean. Separate scales and n labels
prevent Codex n=4 being mistaken for the n=8 population.

The Radient classifier was absent by v1 configuration. Its explicit separate
zero component is not a usage measurement; v1 total = observed model cost.
No inference about a later signed-in classifier's expense is supported.

No point-estimate performance ranking is warranted: n=1 per cell, asymmetric
private loadout, order-dependent warmth, post-hoc task selection, infeasible
checkers, ambiguous tasks, model settings and an infrastructure failure. The
new plots are descriptive and make no inferential claims. Optional historical
statistics resample **tasks**, not repeats; their CIs exclude run-to-run
variance. No pass-rate difference or quality parity is established.

Additional arithmetic clarifications in review prose: the pinned source
universe has **368**, not 369, tasks (multi_apps **101**, not 102); and the
full-arm four-harness frozen score matrix has **14 all-pass, 6 all-fail, 4 mixed**
tasks, not 13/6/5. The review's own enumerated all-pass list has 14 entries.
These corrections do not resolve task feasibility or establish a v2 selection.

## Publication boundary (R6/R7/R9)

Only projected metering metadata and logged scores are shipped, not request
bodies, internal schemas, private instructions, authentication state or kept
artifacts. Task manifest: ID/domain/tier only. Historical JSONs are references,
not an approved public claim. New plots say EXPLORATORY and cite these
corrections. The public loadout differs in counts, bytes, relevance, instruction
paths, and plugins; it is **not** like-for-like v1 and has not been re-metered
here. A future v2 study remains pending preregistration, eligibility/oracle
review, matched treatments, repeats, and real independent evidence.
