# Mesh prior art: what to adopt, what to reject

Status: **research note, supporting the design set**. This is not a requirements
document and nothing here is binding; it exists so the design decisions in
`mesh-network.md` and its detail documents can cite a verified licence and a
read source rather than an impression. Licences marked verified were read as
file text at the URL given; unverified or ambiguous ones are called out as such
rather than guessed. Copyleft and source-available projects are listed as
inspiration only — no code is copied from them.

The one finding that changes a design rather than informing it is recorded at
the end: the offline-member answer needs a *second* mechanism (a bounded
lifetime on the network secret), which is cheap now and a schema change later.


# Mesh prior art: what to adopt, what to reject

**Scope and method.** I read the spine and three detail designs in the worktree (`mesh-network.md`, `mesh-transport-identity.md`, `mesh-session-mobility.md`, `mesh-credentials.md`, `mesh-compute-pool.md`), then went to each project's own LICENSE/COPYING file or project statement and to its own protocol/design doc. **Every licence below that says "verified" was read as file text at the URL given, in this session.** Anything I could not settle says so. RFC 8693, RFC 9700 and RFC 9635 each state in their Copyright Notice that code components extracted from the document are under the (Revised) BSD licence, so patches/examples from them are usable; the FIDO specs are specs, not code licences, and the FIDO Alliance's IPR terms apply to them.

**The three constraints from our own docs that decide every verdict:** identity is an Ed25519 keypair with `device_id` derived from the public key and no CA (`mesh-transport-identity.md` §0.3, §14); pairing transfers a network secret out of band and requires a 6-digit SAS transcribed by a human at *both* keyboards, derived locally and never transmitted (§0.5, §5.2 step 5); and **no inbound reachability is ever assumed** — no UPnP, no hole punching, no STUN (§0.9, §10.4). Anything that needs a control plane, a third-party relay, or a shared CA private key is out on our own terms before licence enters the picture.

## 1. Device pairing: out-of-band secret + short authentication string

| Project | Licence (verified) | Mechanism | Verdict |
|---|---|---|---|
| **Magic Wormhole** | **MIT** — `raw.githubusercontent.com/magic-wormhole/magic-wormhole/master/LICENSE` ("The MIT License (MIT), Copyright (c) 2015 Brian Warner"); README repeats it | PAKE — SPAKE2 (RFC 9382, linked from its own docs) turns a *short, human-pronounceable, single-use* code into a high-entropy shared key; the box "gets only a single guess", and a successful guess makes the intended peer's connection fail with a "crowded"/"scary" error; mailbox server carries the PAKE messages, transit relay only if both peers are NAT'd; everything else encrypted with keys derived from the PAKE secret. Source: `magic-wormhole.readthedocs.io/en/latest/welcome.html` §Safely | **adopt the shape, adapt the mechanism.** The smallest trustworthy CLI scheme is exactly this: short code = the *secret* (one guess, burned on use) + a locally-derived SAS the humans compare. Our invite already burns on mismatch (`mesh-transport-identity.md` §5.1 `redeemed`→`consumed`) — making the redemption leg a PAKE would be a strict upgrade but pulls in a companion `spake2` dependency (licence not verified here). |
| **Signal safety numbers** | **AGPL-3.0** — `raw.githubusercontent.com/signalapp/Signal-Android/main/LICENSE` (verified AGPLv3 — note: *not* GPL-3 as assumed) | 12 groups of 5 digits = 60 digits, derived from a hash over both parties' identity keys *and* the phone number (the phone number is deliberately folded in "to strengthen the relatively short safety number against cryptanalytic attacks using pre-calculated values"); one comparison instead of two fingerprints; QR for in-person. Source: `signal.org/blog/safety-number-updates` | **inspiration only, do not copy code** (AGPL). Adopt the *encoder principles* — base-10 digits (localizable, visually/audibly distinct) and a **single** comparison — and adopt the QR for in-person. Reject 60 digits for a CLI. Our 6 digits are defensible only because they are bound to a live transcript plus a single-use invite (one guess); Signal's must bind long-term keys, which is why theirs is 10× longer. |
| **Syncthing device-ID/QR pairing** | **MPL-2.0** (copyleft, thin) — `raw.githubusercontent.com/syncthing/syncthing/main/LICENSE` | device ID = base32(SHA-256(DER cert)) over a self-signed cert that is "little more than a container for the public key"; TLS with pinned self-signed certs; the docs themselves conclude "Long Device IDs are Painful" and propose **"shorter device IDs with an out of band authentication, a la Bluetooth pairing. You enter a one time PIN into Syncthing and give that PIN plus a short device ID … both sides verify that the other knows the correct PIN before accepting"**. Source: `docs.syncthing.net/dev/device-ids.html` | **adopt the diagnosis, reject the ID.** Their own doc is the argument for our design: an ID-as-key-hash is the right identity, but it is unusable as the human artifact, and the fix they propose *is* our SAS. Their local discovery is also "not protected by crypto" — another reason our §14 rejects mDNS. |
| **Tailscale auth keys** | **BSD-3-Clause** — `raw.githubusercontent.com/tailscale/tailscale/main/LICENSE` | pre-auth key authenticates a node *as the generating user*, or as the key's tag; one-off **or** reusable; expiry 1–90 days; "**Revoking a key does not deauthorize nodes using the key**" — deauthorization is deleting the machine, and the backstop is the node key's own expiry (default 180 days); a key can be marked **Ephemeral** so the node is removed when it goes offline. Source: `tailscale.com/docs/features/access-control/auth-keys` | **adopt for the pool case (A8.1).** This is the named prior art for `mesh-compute-pool.md` §3.2's pre-authorised grant: a one-time, expiring enrollment credential, plus "ephemeral" semantics for a pod that must not leave a ghost member. Reject reusable keys (a stolen reusable key adds devices silently) and reject the control plane. |
| **FIDO/CTAP hybrid (caBLE)** | spec, not code: FIDO Proximity Exchange Protocol, **working draft** `fidoalliance.org/specs/hybrid/proximity-exchange-protocol-v1.0-wd-20260717.html`; reference client `Yubico/python-fido2` — **licence UNCONFIRMED** (LICENSE 404s on both `main` and `master`) | QR carries a `FIDO:/` URL; the phone sends a BLE advertisement; a **doubly-encrypted (TLS + Noise) WebSocket tunnel through a tunnel server** carries a single CTAP command. Source: the PXP spec above + `docs.rs/webauthn-authenticator-rs/.../cable/` | **reject for a CLI.** Needs BLE, a tunnel server and browser-platform support; the only transferable principle is "the QR carries the secret and physical proximity is what proves presence". Mark the licence of the reference implementation unconfirmed. |

**Smallest trustworthy scheme for a CLI:** wormhole's — one shared low-entropy secret, exactly one guess, always burned, plus a SAS derived on each side from the authenticated transcript and compared by a human at each end. We already have all three; the only optional upgrade is PAKE on the redemption leg.

## 2. Overlay/mesh identity, membership distribution, revocation, and the offline member

| Project | Licence (verified) | Mechanism | Verdict |
|---|---|---|---|
| **Nebula** (Slack) | **MIT** — `raw.githubusercontent.com/slackhq/nebula/master/LICENSE` ("Copyright (c) 2018-2019 Slack Technologies, Inc.") | Noise-based; a **per-network CA signs host certificates** that assert IP + name + **groups**; lighthouses for discovery (optional UDP hole punching); CA default lifetime 1 year, host certs expire 1s before the CA (`-duration` to shorten). **Revocation = rotate the CA**; fine-grained blocklisting is a *commercial* (Defined Networking) feature. Sources: `README.md`; `nebula.defined.net/docs/guides/rotating-certificate-authority/` | **reject the PKI, adopt one idea.** A shared CA private key held by every member cannot distinguish devices and its revocation is "revoke everyone" — strictly worse than our epoch rotation, which names the removed device (§8.1). Adopt "certificates as the identity envelope" only if we ever need group/tag-based firewalling; adopt *lighthouse* as the vocabulary for a future discovery/forwarding member (§14). |
| **Innernet** (Square/tonari) | **MIT** — `raw.githubusercontent.com/tonarino/innernet/main/LICENSE` | Per-network coordination server holds the WireGuard keys and the CIDR layout; a new peer receives a **single-use invitation file** ("can only be used once to initialize the peer"); the server distributes peer configs and CIDR-derived ACLs; the server never sees traffic. Source: `README.md` | **adopt the single-use invite, reject config re-pull.** Removal in innernet means every peer must fetch new config; our membership check happens at handshake against the current epoch (§6.2 step 6), which covers peers that never re-pull. |
| **Tailscale / Headscale** | Tailscale **BSD-3-Clause** (above); Headscale **BSD-3-Clause** — `raw.githubusercontent.com/juanfont/headscale/main/LICENSE` | Node key registered with a coordination server; authorization is control-plane state re-evaluated on contact; node keys expire (180 days default); deauthorize = delete the machine; DERP relays are blind. Source: the auth-keys doc above | **adopt the two-tier revocation model.** (a) membership evaluated fresh at every contact; (b) **every credential has a bounded lifetime as the backstop** for the device that never comes back. We have (a) only. |
| **ZeroTier** | **MPL-2.0 for the agent, and NOT open source for the controller**: `LICENSE.txt` → "See LICENSE-MPL.txt for … node/, osdep/. service/" and `nonfree/LICENSE.md`, which says the Controller is under a *source-available, non-commercial* licence and "is **not 'open source' as defined by the Open Source Initiative**". | 40-bit address derived from the public key; a network ID embeds the **controller's** node address; the controller "admits members, issues certificates, and issues default configuration"; joining devices must be **authorized**; public networks cannot de-authorize anyone. Sources: `docs.zerotier.com/protocol/`; `docs.zerotier.com/networks/` | **adopt the identity derivation, reject the topology and the licence.** We already derive `device_id` from the pubkey (§3.1) and hold the member set in the network record — this is ZeroTier's shape without the controller. Do not read their controller code at all. |
| **WireGuard** | **GPL-2.0** — `raw.githubusercontent.com/WireGuard/wireguard-tools/master/COPYING` (verified GPLv2; the kernel module is GPL-2.0 too) | Identity = raw public key. "Cryptokey routing" maps each peer's public key to the set of allowed source/dest IPs; **there is no membership distribution at all** — configuration is out of band, and revocation is deleting the peer entry (rotating your own key invalidates everyone). (Project site `wireguard.com` failed its TLS handshake from this host; the model description is the project's well-known one, not re-fetched.) | **inspiration only** (GPL). Adopt "peer entry = public key + the names it may use" as the table our `Authorizer` already is (`OP_CAPABILITY`), and adopt the argument for *ephemeral* keys that our §14 already makes against static-static DH. Reject deriving membership from config push — that is exactly the problem we are solving. |
| **OpenZiti** | **Apache-2.0** — `raw.githubusercontent.com/openziti/ziti/main/LICENSE` | Identities are **X.509 certificates mapped to a controller-stored identity**, with **mutual TLS in both directions**; enrolment by a **single-use one-time token (JWT) that expires 24h after identity creation** and is consumed on enrolment; authorization is policy over identities/attributes. Source: `openziti.io/docs/learn/core-concepts/identities/overview` | **adopt the enrolment token and the mutual-auth-always rule**; reject the PKI/controller dependency. Removal of an identity is a controller record change — the same read (membership is state, checked at connect) as ours, but centralised. |
| **Yggdrasil** | **LGPL-3.0 with a linking exception** (copyleft) — `raw.githubusercontent.com/yggdrasil-network/yggdrasil-go/master/LICENSE` | Global public IPv6 overlay, end-to-end encrypted, spanning-tree routing, **no authority of any kind**: peering is uncontrolled unless you set a local `AllowedPublicKeys` allow-list; "a public network … should take adequate precautions"; no revocation mechanism exists. Source: `README.md`, `yggdrasil-network.github.io/faq.html` | **reject wholesale.** No membership, no revocation, needs TUN/root, and the licence is copyleft. (The FAQ does not state the address-from-key derivation; that detail is unverified here.) |

**The offline-member answer, as the prior art converges on it:** (i) membership is *state re-evaluated on every contact* (ZeroTier's controller, Tailscale's control plane, OpenZiti's identity record — and our epoch check at handshake step 6), **and** (ii) *every credential has a bounded lifetime* so a device that never contacts again ages out (Nebula's 1-year certs, Tailscale's 180-day node keys, OpenZiti's 24-hour enrolment token). §8.4 gives us (i) and nothing gives us (ii) — the removed-device case is covered, but a *still-member* device that vanishes holding a current secret is not. Adding a max age to the network secret (forcing a reconcile-and-rotate after N days, even from live members) is cheap now and expensive later.

## 3. NAT traversal and relaying

| Project | Licence (verified) | Mechanism | Verdict |
|---|---|---|---|
| **Tailscale DERP** | **BSD-3-Clause** (Tailscale LICENSE, above) | A relay that "blindly forwards already-encrypted traffic": private keys never leave the device, so "it's impossible for a DERP server to decrypt your traffic"; a **DERP map** is handed out by the coordination server, the client picks a home DERP by latency, discovery uses DISCO packets, and relaying is the fallback when a direct path fails. Source: `tailscale.com/docs/reference/derp-servers` | **ADOPT the shape — this is our §10.4 WAN path, named.** The adoptable content is the *rule*: a relaying member forwards ciphertext it cannot read; **it learns only metadata** (who talks to whom, and how much), and we should say that plainly in our threat notes. |
| **libp2p Circuit Relay v2** | spec; implementation `go-libp2p` **MIT** — `raw.githubusercontent.com/libp2p/go-libp2p/master/LICENSE` | Split into `hop` (client→relay) and `stop` (relay→target); **explicit reservation** of relay resources with signed vouchers, and **limited relaying** (duration + byte caps) because v1's unlimited relays were "a continuous over-subscription" and "an expensive proposition". Source: `raw.githubusercontent.com/libp2p/specs/master/relay/circuit-v2.md` | **adopt the limits, reject the protocol.** If we ever add §14's `net_forward`, it must be reservation-based and capped per link (duration + bytes), not an unbounded byte pipe. |
| **STUN / TURN** | specs; `coturn` **BSD-3-Clause** — `raw.githubusercontent.com/coturn/coturn/master/LICENSE` | STUN discovers your reflexive address; TURN is a **relayed transport with allocations, permissions and credentials**. | **reject for v1.** Needs rendezvous infrastructure, UDP, and a credential-issuing server; §10.4 rejects it and the Tailscale blog below agrees it is the long tail of a much bigger machine. |
| **Syncthing relays** | **MPL-2.0** (same repo) | Relays are untrusted by construction: "the connection between two devices is still end to end encrypted, the relay only retransmits the encrypted data much like a router", but "the relay knows your IP and device ID" and "can see the amount of traffic"; you can pin your own relay by device ID. Source: `docs.syncthing.net/users/relaying.html` | **adopt the honesty.** Copy the wording discipline: state what the relay learns, do not imply end-to-end secrecy of metadata. `relay://host/?id=<device ID>` is also a good precedent for "a relay is named by a key, not a hostname". |
| **iroh** | **MIT OR Apache-2.0** (dual) — `raw.githubusercontent.com/n0-computer/iroh/main/LICENSE-MIT` + README badges | "Dial by public key"; hole-punch when necessary, otherwise fall back to "an open ecosystem of public relay servers"; QUIC underneath. | **adopt the API shape, reject the stack.** "Dial by key, let the transport choose the path" is our §6; QUIC is rejected in §14 and a Rust/QUIC dependency is wrong for a Python service. |
| **"How NAT traversal works"** (Tailscale) | blog (no code licence) — `tailscale.com/blog/how-nat-traversal-works` | The canonical recipe: a UDP protocol, direct socket control, a side channel, a couple of STUN servers, fallback relays, then probe every candidate path and upgrade/downgrade as it changes. Its security conclusion: once paths change at runtime "IP-based security becomes meaningless … you must have at least end-to-end authentication". | **adopt the security conclusion, reject the machinery.** This is the external authority for "authentication lives in our handshake, not in the network" (§6.1). |

**Minimum viable with no inbound reachability:** direct if either side can dial; otherwise a **blind, capped relay that forwards ciphertext** (DERP-shaped) reached by the dial-out side; never advertise reachability we have not proven (`lop network doctor`, §10.4); and state the two-NAT'd-peers-with-no-third-party case as unlinkable rather than papering over it.

## 4. Session lifecycle for E2E remote terminals

| Project | Licence (verified) | Mechanism | Verdict |
|---|---|---|---|
| **abduco** | **ISC** — `raw.githubusercontent.com/martanne/abduco/master/LICENSE` and README | The smallest thing in the space: "programs can be detached … and later reattached"; session list marks `*` = a client connected, `+` = the command terminated with the **exit status preserved and reported on reattach**; `-r` attaches **read-only** (explicitly "not a security feature, but … a convenient way to avoid accidental keyboard input"); **"resize request are only processed if they are initiated by the most recently connected, non read only client"**; socket lives in a 0700 dir. | **ADOPT — the highest-value policy in this whole survey.** The resize rule is exactly what a multi-viewer mesh needs (a phone attaching must not reflow the desktop's session), read-only attach is our "observer" capability, and "keep the exit status across a detach" is a lifecycle detail a move between peers can silently lose. |

| **Mosh** | **GPL-3.0-or-later** — `raw.githubusercontent.com/mobile-shell/mosh/master/COPYING`; `mosh.org` prints "License GPLv3+ … or later" | Roaming across IP changes, local echo/prediction, SSP state synchronisation — and "client and server are executables run by an ordinary user and **last only for the life of the connection**"; "No privileged code. **No daemon.**" | **inspiration only** (GPL) **and reject the lifecycle**: its server dies with the client, which is the exact opposite of R9. | **Zellij** | **MIT** — `raw.githubusercontent.com/zellij-org/zellij/main/LICENSE.md`; README "License: MIT" | Session manager, detach/reattach, layouts, plugins (WASM), a built-in **web client** so "a terminal is optional". | **adopt** the "many viewers, one session, one of them is a browser" precedent for our desktop/TUI-over-mesh story; reject the plugin surface. |
| **tmate** | **README says "tmux and tmate are BSD-licensed"; `COPYING` carries the tmux ISC text** — `raw.githubusercontent.com/tmate-io/tmate/master/COPYING`. **Statement is internally inconsistent** (BSD vs ISC) — permissive either way; mark the *name* as ISC-style/BSD-family, not a precise SPDX id. | A tmux fork whose whole trick is **outbound-only reachability**: the session lives on a public relay reached by `ssh -R`. (`tmate.io` did not resolve from this host; the man page in-tree is a stub — this mechanism description is the project's well-known one, not re-read here.) | **adopt the outbound-only model** (it is what `lop tunnel` already gives us) and the read-only share; **reject the third-party relay** on §0/§4's zero-trust terms. |
| **`ssh -R` patterns** | n/a (OpenSSH is BSD-2/ISC-family) | Reverse forward through any host you can reach — the primitive that makes a no-inbound topology work. | **adopt as v0 of the WAN path**, which is precisely §10.4's sanctioned Radient tunnel. |

**What to copy, precisely:** detached runtime owns the session (ours already); attach = viewer, never owner (ours); **width owned by the most-recent non-read-only client** (abduco — new); a **read-only observer capability** (abduco — new, and it falls out of our `capabilities` set); **reflow on reattach** at the new width; and **exit status surviving a detach/move**.

That is the right amount of CRDT for this problem. |

## 7. Credential brokering: "ask the owning device for a usable, scoped, short-lived token"

**The name.** The protocol is **OAuth 2.0 Token Exchange (RFC 8693)**; the semantics are **delegation** — §1.1 is literally titled *Delegation vs. Impersonation Semantics*, and the issued token carries an **`act`** (actor) claim plus a **`may_act`** (authorized-actor) claim on the subject token. The architecture is a **credential broker**; the enterprise name for the flow is **on-behalf-of (OBO)**; the standards body has now named the topology too (SPIFFE Broker API, below).

## What we should copy, ranked

1. **abduco's attach discipline (ISC)** — *width owned by the most-recent non-read-only client*, a read-only observer attachment, and the exit status preserved and reported across a detach. Zero dependencies, pure policy, prevents a real bug (a phone viewer reflowing the desktop's session) and closes a lifecycle hole a peer move can create. Highest value per line of code in this survey.
2. **DERP-shaped blind relay as the sanctioned WAN path (BSD-3)** — one member forwards ciphertext it cannot decrypt, is named by its key, and is capped per link (libp2p v2's reservation + duration/byte limit). It is already our §10.4; the adoptable content is the *rule* plus the honest statement of what a relay learns (`docs.syncthing.net/users/relaying.html` says it well).
3. **Content-addressed immutable session blobs + a flat digest frontier (restic BSD-2, git's negotiate-then-pack pattern)** — the plan's `{name, size, mtime_ns, digest}` and `attachments/<digest>.bin` are already this shape; restic supplies the verification and GC discipline for free and its licence is permissive.
4. **Slurm-shaped metering events (GPL-2.0, copy the schema not the code) + Kubernetes Job lifecycle (Apache-2.0) + Tailscale's pre-authorised expiring enrollment credential with ephemeral semantics (BSD-3)** — total and peak kept distinct, a (workload, member, session) attribution triple, completion-and-cleanup on teardown, and a one-time credential that cannot add a second device. This is A8.1 answered with prior art instead of invention.

*Honourable mention:* **SPIFFE's Broker API** gives `mesh-credentials.md` the standard vocabulary it currently lacks — the relay is a *broker*, the operation is a *delegation* (RFC 8693), and the actor is recorded in an `act`-style claim.

## What we should not

- **CRDTs (Automerge, Yjs — both MIT) as the session model.** They exist to merge concurrent writers, which `exclusive-move-v1` and the single lease forbid by design, and the transcript is compacted in place, which a CRDT cannot express. Steal only the state-vector idea, which we already have.
- **STUN/TURN/ICE and hole punching (RFC 5389/8656, coturn BSD-3).** Rendezvous infrastructure, UDP-only payoff and unpredictable reachability; §10.4 already rejects it and Tailscale's own blog calls the traversal machine "quite complicated".
- **mDNS/Bonjour discovery.** A privacy leak on untrusted LANs (§14 rejects it), and Syncthing's local discovery is explicitly "not protected by crypto".
- **Certificate-authority PKI (Nebula's CA, mTLS with a per-network CA, OpenZiti's controller).** A CA whose private key every member holds cannot distinguish devices, and its revocation is "rotate the CA". §14 rejects it on three grounds; this survey adds that the smallest permissive alternative (Nebula) still needs a CA rotation to evict one node.
- **Any central control plane as a component** (Tailscale/Headscale's coordination server, ZeroTier's controller, NetBird's management/signal/relay). Useful as architecture to read; adopting it contradicts "a relay per install, no third party" (R1/R4).
- **Copyleft, source-available and non-open licences as code sources:** Nomad and Vault (**BUSL-1.1**), Teleport (**AGPL-3.0**), NetBird's `management/`, `signal/`, `relay/`, `combined/` (**AGPLv3**, the rest BSD-3), Signal-Android (**AGPL-3.0** — note: not GPL-3), mosh (**GPL-3.0-or-later**), git and wireguard-tools (**GPL-2.0**), Slurm (**GPL-2.0**), Yggdrasil (**LGPL-3.0**). Read them; copy no code. ZeroTier is worse: the controller is **not open source at all**, it is source-available for non-commercial use.
- **Ray** for the pool (long-lived cluster with a head node) and **Fly.io/Modal** as anything but an API shape to imitate (proprietary, no licence to copy).
- **QUIC/iroh/aioquic** — permissively licensed but rejected in §14, and a Rust/QUIC stack is wrong weight for a Python service.

**One finding that should change the design, not just inform it:** the offline-member answer in the prior art is *two* mechanisms, and §8.4 has only the first. Membership re-evaluated at every contact (ours: the epoch/member check at handshake step 6) covers the *removed* device; a **bounded credential lifetime** — Nebula's expiring certs, Tailscale's 180-day node keys, OpenZiti's 24-hour enrolment token — is what covers the *still-member* device that never comes back. A max age on the network secret, forcing a reconcile-and-rotate even among live members, is cheap to add now and a schema change later.
