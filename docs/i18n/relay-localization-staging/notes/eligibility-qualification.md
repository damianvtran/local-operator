### Eligibility mechanism note — contract, limitation and bounded proposal
Source: independent architect session `279e3a78b923`, actual model **anthropic/claude-sonnet-5-5**, no fallback; primary read-only `pr2329-pernamespace-eligibility-note.md`. Integrator coder aggregates the findings below; this is **not an eligibility code change**, HTTP test or additional review round.

**Current contract, not a demonstrated contract bug.** `generate.py::_shipped_locales` (`269-286` at57bcb) requires EVERY namespace a locale carries to have a fresh `passed` row. `docs/design/i18n.md:580-584`, `docs/I18N.md:35-37` and `test_generate.py::test_a_carried_namespace_without_a_ledger_entry_un_ships` document/test this fail-closed policy. The per-namespace amendment (`i18n.md:589-603`) narrows which namespaces are checked—an uncarried English-only namespace does not unship a locale—but does NOT make an unpassed carried namespace independently eligible.

**Granularity limitation:** a pending/stale carried namespace therefore removes its locale globally, so unrelated previously audited `wire.*`/`tui.*` messages fall back to English. This is collateral loss under the documented locale-wide eligibility policy, even though missing-namespace fallback can otherwise be per-namespace (`messages.py:113-123`, `text.py:105-114`). Changing the granularity is a product/security contract decision, not a one-line bug fix.

**Options / minimum proposal**
- **For this PR: stage held candidates outside active catalogue/ledger inputs** (already done in57bcb). Preserve exact pins, reports and failed/withdrawn history on the dedicated durable archive branch. Later promote files + genuinely complete passed rows + generated data only after actual rendered/publication audit, via the separately authorized locale PR. No gate/RFC implementation needed for this minimal split.

Do NOT merely ignore pending rows or silently distribute held catalogue files. No new issue/PR/mechanism change proposed into this scope.
